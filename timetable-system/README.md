# Smart Manual Timetable System

Общий Docker-запуск вместе со студенческим UTB2, локальная проверка и размещение
на `okak.asia` / `app.okak.asia`: **[инструкция](deploy/README.md)**.

MVP-прототип интерактивной системы ручного составления университетского
расписания: пул нераспределённой нагрузки, drag-and-drop в сетку «дни ×
пары», проверка конфликтов в реальном времени, умный выбор аудитории.

Дизайн и обоснование решений: [docs/superpowers/specs/2026-09-14-timetable-system-design.md](docs/superpowers/specs/2026-09-14-timetable-system-design.md).

## Требования

- Python 3.11+
- Node.js 18+

## Запуск бэкенда

```bash
cd backend
python -m venv .venv
```

Активация окружения:

```bash
# Windows
.venv\Scripts\activate
```

```bash
# macOS / Linux
source .venv/bin/activate
```

Установка зависимостей и наполнение БД тестовыми данными:

```bash
pip install -r requirements.txt
python seed.py
```

`seed.py` пересоздаёт `timetable.db` с нуля — можно перезапускать в любой
момент, чтобы сбросить расписание к исходному состоянию. `python in.py` —
то же, но с реальными кафедрами и аудиториями корпуса №1 КазУТБ.

`python import_rooms.py` — добавить в текущую БД (без удаления) кафедры,
блоки 1–3 и аудитории из приказа о закреплении аудиторного фонда;
`--all` — ещё пр. Республики 54/2 и Дом студентов, `--dry-run` — только показать.

Старую `timetable.db` пересоздавать не обязательно: при старте `main.py`
сам добавит новые колонки (тип помещения, кафедры) — см. `database/migrate.py`.

Запуск сервера:

```bash
# Локальный запуск по HTTP (macOS, Linux, Windows):
python run_dev.py
```

API поднимется на `http://127.0.0.1:8000`. `run_dev.py` автоматически включает
cookie для локального HTTP и использует БД из папки `backend`. На сервере
используйте production-команду ниже.

Если после успешного входа (`200`) появляются ответы `401`, остановите backend
и запустите его через `python run_dev.py`, затем войдите снова. Обычный запуск
через `uvicorn` по умолчанию устанавливает cookie только для HTTPS.

### Проверка бизнес-логики

```bash
python test_validation.py   # ручная расстановка: конфликты и предупреждения
python test_room_options.py # подбор кабинетов: совпадение проверок и число SQL-запросов
python test_scheduler.py    # автогенерация через БД
python test_planner.py      # алгоритм автогенерации и правила аудиторий (без БД)
python test_references.py   # удаление записей справочников
```

Каждый должен напечатать `OK`.

## Запуск фронтенда

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Открыть `http://localhost:5173`. Vite проксирует запросы `/api` на
`http://127.0.0.1:8000`, поэтому бэкенд должен быть уже запущен.

## Авторизация и размещение на сервере

До первого входа создайте пользователя из папки `backend`, в активированном
Python-окружении:

```bash
python manage_users.py admin
```

Команда запросит пароль дважды (не менее 12 символов, ввод скрыт). Вместо
`admin` можно указать свой логин. Повторный запуск для того же логина меняет
пароль и завершает все его сеансы. Открытой регистрации и пароля по умолчанию
нет. Все созданные пользователи имеют полный доступ к расписанию и справочникам.
Учётные записи и сеансы сохраняются в той же `timetable.db`, что и расписание.
Запускайте команды и сервер из одной папки `backend`; сохраняйте резервную копию БД.

После открытия сайта сначала отображается форма входа. Сервер также проверяет
авторизацию для всех API расписания и справочников. Сеанс действует 12 часов,
сохраняется при обновлении страницы и отзывается кнопкой «Выйти». Пароли
хранятся как scrypt-хеши; случайный ключ сеанса — в HttpOnly/SameSite cookie,
в БД хранится только его хеш. Лимит входа: 10 попыток на логин и 100 на IP
за 15 минут (включая успешные). За reverse proxy IP может быть общим — настройте
дополнительное ограничение запросов на прокси при необходимости.

Для production:

1. Соберите фронтенд: `cd frontend && npm ci && npm run build`.
2. Раздавайте `frontend/dist` через Nginx/Caddy с **HTTPS**. Проксируйте `/api/`
   на FastAPI (`127.0.0.1:8000`) на том же домене, сохраняя путь `/api/`.
3. Запускайте `uvicorn main:app --host 127.0.0.1 --port 8000` из `backend`.
   Не задавайте `AUTH_COOKIE_SECURE=false` на сервере: по умолчанию cookie
   передаётся только по HTTPS. Для локальной разработки по HTTP эта переменная
   должна быть `false` (PowerShell: `$env:AUTH_COOKIE_SECURE="false"`).
4. Не публикуйте файлы БД, исходники backend и порт FastAPI напрямую.
   Swagger/OpenAPI отключены. Существующую БД можно использовать без пересоздания:
   таблицы авторизации добавляются автоматически. Не запускайте `seed.py`/`in.py`
   на рабочей БД — это команды сброса данных.

Проверка авторизации (на изолированной тестовой БД):

```bash
pip install -r requirements-dev.txt
python test_auth.py
```

## Как пользоваться

1. Слева — карточки нераспределённой нагрузки, справа — сетка «дни × пары».
   Кнопка «Составить автоматически» стирает текущую расстановку и строит
   расписание заново: старается не оставлять окон между парами у групп и
   не менять аудиторию/корпус без необходимости. Часы, для которых не
   нашлось подходящей аудитории, остаются в пуле — сколько именно, видно
   в уведомлении сверху.
2. Перетащите карточку на ячейку — рамка подсветится зелёным (можно
   ставить), жёлтым (можно, но есть предупреждение — например, не хватает
   мест) или красным (нельзя: аудитория/преподаватель/группа заняты).
3. При отпускании на зелёную или жёлтую ячейку откроется список аудиторий,
   отсортированный по пригодности — выберите нужную.
4. Уже поставленную пару можно перетащить в другую ячейку (перенос) или
   убрать кнопкой «×» рядом с ней — она вернётся в пул.
5. Переключатель сверху меняет, что показывает сетка и пул: по группам, по
   аудиториям или по преподавателям.
6. Вкладка «Справочники» — создание, редактирование и удаление корпусов,
   аудиторий, преподавателей, групп, предметов, слотов и самой нагрузки.
   Удаление каскадное: например, удаление преподавателя удаляет все его
   карточки нагрузки вместе с уже расставленными по ним парами.

## Публикация в студенческое приложение UTB2

Кнопка «Опубликовать для студентов» отправляет полный список групп и расставленных
пар в UTB2. Пока вы редактируете черновик, студенты видят предыдущую публикацию.
Добавленные группы появляются, переименованные обновляются, отсутствующие группы
удаляются вместе с парами. Публикуются и группы без пар; нерасставленная нагрузка
не публикуется. Конфликты времени групп, преподавателей и аудиторий блокируют
публикацию. Для одинаковых названий групп при публикации добавляется курс (например,
«ДЗ-252 · 1 курс»). Название с курсом должно быть уникальным и не длиннее 50 символов;
названия предметов — до 150, корпус с аудиторией — до 50 (контракт UTB2).

Настройки в `backend/.env` (загружаются при старте):

```dotenv
STUDENT_PUBLISH_URL=http://127.0.0.1:8001/api/v1/publication
PUBLISH_SECRET_KEY=ваш-случайный-секрет-не-короче-32-символов
```

Один и тот же ключ задаётся в `UTB2/backend/.env`. На сервере используйте HTTPS
в `STUDENT_PUBLISH_URL`. HTTP разрешён только для localhost. Ключ не должен попадать
во фронтенд. После изменения настроек перезапустите backend обоих приложений.

UTB2 должен быть запущен и обновлён до версии с приёмом публикаций. Пока настройки
отсутствуют, кнопка отключена. При первой публикации прежнее ручное расписание
UTB2 полностью заменяется. Совпавшие по названию группы сохраняют свои студенческие
ID; далее используется постоянный UUID группы, включая при переименовании.
Полностью пустая публикация очищает группы и расписание UTB2 — это явно указано
в подтверждении перед публикацией.

Снимки и номера версий сохраняются в БД сотрудников. При ошибке сети интерфейс
не сообщает об успехе: если ответ потерялся, данные могли уже дойти; повторная
публикация безопасно отправляет новую версию текущего черновика. Старые версии
не могут перезаписать новые. Публикации разных сотрудников упорядочиваются по
номеру версии. Не запускайте команды сброса БД на сервере: смена идентификатора
источника блокируется принимающей стороной.

Проверка обоих приложений на временных БД:

```bash
cd backend
.venv/bin/pip install -r requirements-integration.txt
.venv/bin/python test_publication.py
```

UTB2 ожидается рядом с этим проектом или по пути `UTB_PROJECT_DIR`.
Инструкции обновления UTB2 и остановки старого контейнера бота находятся
в README проекта UTB2.
